# GYM AI — передача проекта

Telegram Mini App для тренировок: календарь, редактор программы, история тренировок, AI-коуч.
Бэкенд на Node.js + Turso (libSQL), фронтенд — один статический `index.html`.

- Бот: [@GymAi_robot](https://t.me/GymAi_robot)
- Mini App: https://gym-ai-3f0d63ky.agent.mira.tg
- API: https://gymai-backend-ev1z.onrender.com

## Репозитории

| Репозиторий | Что внутри |
|---|---|
| `spspsaaa/gymai-app` | Фронтенд. Весь UI в одном `index.html` (243 КБ) + PWA-обвязка |
| `spspsaaa/gymai-backend` | Бэкенд. `server.js` + `src/{ai,db,telegram}.js` |

## Бэкенд

```
server.js          express-приложение: auth, state, coach, admin, telegram-вебхук
src/telegram.js    разбор и HMAC-проверка Telegram initData
src/ai.js          AI-коуч через любой OpenAI-совместимый эндпоинт
src/db.js          хранилище: Turso/libSQL, фолбэк на локальный JSON-файл
```

### Переменные окружения

Все секреты живут **только в env Render** — в репозитории их нет, в коде тоже.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от @BotFather |
| `TG_WEBHOOK_SECRET` | Секрет вебхука. **Должен совпадать** с `secret_token`, которым зарегистрирован вебхук |
| `TURSO_URL` / `TURSO_TOKEN` | База Turso/libSQL. Без них — фолбэк на локальный JSON (данные теряются при рестарте) |
| `AI_API_KEY` | Ключ AI-провайдера |
| `AI_BASE` | Базовый URL OpenAI-совместимого API. Если содержит `openrouter.ai` — включается цепочка фолбэков |
| `AI_MODEL` | Модель. Обязательна, если `AI_BASE` не OpenRouter |
| `AI_TIMEOUT_MS` | Таймаут запроса к AI, по умолчанию 30000 |
| `INITDATA_MAX_AGE_SEC` | Максимальный возраст initData в секундах, по умолчанию 30 дней. `0` отключает проверку |
| `ALLOW_UNVERIFIED` | `1` принимает initData без проверки подписи. **В проде `0`** — иначе любой может выдать себя за любого юзера |
| `ADMIN_SECRET` | Секрет для `/api/admin/plan` |
| `WEBAPP_URL` | Публичный адрес мини-апа |
| `FREE_COACH_LIMIT` | Лимит запросов к AI-коучу для free, по умолчанию 20 |

### Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка живости, показывает наличие ключей |
| POST | `/api/auth` | Обмен initData на токен сессии |
| GET | `/api/state` | Чтение состояния пользователя |
| PUT | `/api/state` | Запись состояния |
| POST | `/api/coach` | Запрос к AI-коучу |
| POST | `/api/admin/plan` | Выдача/отзыв Pro (`x-admin-secret`) |
| POST | `/api/tg/webhook` | Вебхук Telegram (`x-telegram-bot-api-secret-token`) |

Авторизация: `Authorization: Bearer <token>` либо `initData` в теле. Токен живёт в БД, поэтому переживает рестарт Render.

### Развёртывание

Render, триггер `commit` на `main`. Если автодеплой не сработал — вручную через Render API.

**Порядок при смене `BOT_TOKEN`:** сначала выпустить новый токен в @BotFather, обновить `BOT_TOKEN` в env, задеплоить, затем перерегистрировать вебхук:

```
POST https://api.telegram.org/bot<NEW_TOKEN>/deleteWebhook
POST https://api.telegram.org/bot<NEW_TOKEN>/setWebhook
     ?url=https://gymai-backend-ev1z.onrender.com/api/tg/webhook
     &secret_token=<TG_WEBHOOK_SECRET>
     &allowed_updates=["message"]
```

Смена `secret_token` требует пересоздания вебхука — `setWebhook` поверх существующего секрет не меняет.

## Фронтенд

Один файл `index.html`: разметка, стили и весь JS. Общается с бэкендом напрямую, хранит состояние в `localStorage` и синхронизирует на сервер.

Вкладки: **Зал** (календарь недели/месяца), **Тренировка** (работа с подходами, добавление упражнений вне плана), **Программа** (редактор плана, пресеты), **История** (разворачиваемые записи), **Профиль**.

Тарифы: AI Free — 10 сообщений коуча в день и одна программа; AI Pro — безлимит, генератор программ, разбор техники, экспорт. Счётчик обновляется в 00:00 UTC.

PWA: `manifest.webmanifest` + `sw.js`. Кэш service worker — `gymai-v3`; **при изменении статики версию поднимать**, иначе пользователи получат старую версию из кэша.

## Что стоит знать при доработке

**`index.html` на 243 КБ — один файл.** Первое, что стоит сделать при развитии проекта: разнести на модули. Редактировать в таком виде больно.

**База упражнений захардкожена в `index.html`.** В редакторе программы есть поиск по каталогу, но сам каталог — массив в коде. Для мультипользовательской версии нужна таблица.

**Полный каталог упражнений лежит в `prototypes/`, а не в основной версии.** В `index.html` только 11 записей в `exerciseGuides` без полей `zone` / `muscle` / `tech`. Полные 53 упражнения с описанием техники и привязкой к 9 мышечным зонам — в `prototypes/exflow/`, оттуда же вынесен `exercise_library.json`. Форматы основной версии и прототипа несовместимы, при внедрении нужно свести к одному. Подробности в `prototypes/README.md`.

**Админка по-прежнему в клиенте.** Пароль админа лежит в коде страницы, вкладка открывается по хешу `#admin`. Это защита от случайного входа, а не от злоумышленника.

**Сессии не имеют срока жизни.** Токен в БД живёт бессрочно. Если понадобится — добавить `expires_at` в таблицу `sessions`.

**`reserveCoach` возвращает `used` на единицу устаревшим** — считает значение до `UPDATE`. На лимит не влияет (проверка идёт по `rowsAffected`), но в ответе `402` число неверное.

**Лимит coach обновляется в 00:00 UTC.** Серверное время, не локальное.

**Публикация мини-апа** идёт через платформу mira.tg, не через GitHub Pages. `index.html` в репозитории — источник, публикация — отдельный шаг.

## Полезные команды

```bash
# локальный запуск бэкенда без Turso (фолбэк на JSON)
cd gymai-backend && npm install && BOT_TOKEN= node server.js

# проверка синтаксиса
node --check server.js && node --check src/ai.js
```

## Что уже сделано и проверено

- HMAC-проверка initData с `timingSafeEqual`, отсечкой по возрасту и защитой от битого ввода
- Вебхук требует `TG_WEBHOOK_SECRET`, сравнение константное
- Квота AI-коуча резервируется атомарно до вызова и возвращается при ошибке
- `upsertUser` пишет только переданные поля — без гонки чтения-записи
- Пустой ответ модели не показывается пользователю: перебор фолбэков, `reasoning` не используется
- Таймаут запросов к AI, битый JSON отдаёт 400, внутренние ошибки наружу не утекают
