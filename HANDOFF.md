# GYM AI — передача проекта

Telegram Mini App для тренировок: календарь, редактор программы, история тренировок, AI-коуч.
Бэкенд на Node.js + Turso (libSQL), фронтенд — один статический `index.html`.

- Бот: [@GymAi_robot](https://t.me/GymAi_robot)
- Mini App: https://gym-ai-3f0d63ky.agent.mira.tg
- API: https://gymai-backend-ev1z.onrender.com

## Репозитории

| Репозиторий | Что внутри |
|---|---|
| `spspsaaa/gymai-app` | Фронтенд. Весь UI в одном `index.html` (243 КБ) + PWA-обвязка |
| `spspsaaa/gymai-backend` | Бэкенд. `server.js` + `src/{ai,db,telegram}.js` |

## Бэкенд

```
server.js          express-приложение: auth, state, coach, admin, telegram-вебхук
src/telegram.js    разбор и HMAC-проверка Telegram initData
src/ai.js          AI-коуч через любой OpenAI-совместимый эндпоинт
src/db.js          хранилище: Turso/libSQL, фолбэк на локальный JSON-файл
```

### Переменные окружения

Все секреты живут **только в env Render** — в репозитории их нет, в коде тоже.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от @BotFather |
| `TG_WEBHOOK_SECRET` | Секрет вебхука. **Должен совпадать** с `secret_token`, которым зарегистрирован вебхук |
| `TURSO_URL` / `TURSO_TOKEN` | База Turso/libSQL. Без них — фолбэк на локальный JSON (данные теряются при рестарте) |
| `AI_API_KEY` | Ключ AI-провайдера |
| `AI_BASE` | Базовый URL OpenAI-совместимого API. Если содержит `openrouter.ai` — включается цепочка фолбэков |
| `AI_MODEL` | Модель. Обязательна, если `AI_BASE` не OpenRouter |
| `AI_TIMEOUT_MS` | Таймаут запроса к AI, по умолчанию 30000 |
| `INITDATA_MAX_AGE_SEC` | Максимальный возраст initData в секундах, по умолчанию 30 дней. `0` отключает проверку |
| `ALLOW_UNVERIFIED` | `1` принимает initData без проверки подписи. **В проде `0`** — иначе любой может выдать себя за любого юзера |
| `ADMIN_SECRET` | Секрет для `/api/admin/plan` |
| `WEBAPP_URL` | Публичный адрес мини-апа |
| `FREE_COACH_LIMIT` | Лимит запросов к AI-коучу для free, по умолчанию 20 |

Авторизация: `Authorization: Bearer <token>` либо `initData` в теле. Токен живёт в БД, поэтому переживает рестарт Render.

### Развёртывание

Render, триггер `commit` на `main`. Если автодеплой не сработал — вручную через Render API.

**Порядок при смене `BOT_TOKEN`:** сначала выпустить новый токен в @BotFather, обновить `BOT_TOKEN` в env, задеплоить, затем перерегистрировать вебхук:

```
POST https://api.telegram.org/bot<NEW_TOKEN>/deleteWebhook
POST https://api.telegram.org/bot<NEW_TOKEN>/setWebhook
     ?url=https://gymai-backend-ev1z.onrender.com/api/tg/webhook
     &secret_token=<TG_WEBHOOK_SECRET>
     &allowed_updates=["message"]
```

Смена `secret_token` требует пересоздания вебхука — `setWebhook` поверх существующего секрет не меняет.

## Фронтенд

Один файл `index.html`: разметка, стили и весь JS. Общается с бэкендом напрямую, хранит состояние в `localStorage` и синхронизирует на сервер.

Вкладки: **Зал** (календарь недели/месяца), **Тренировка** (работа с подходами, добавление упражнений вне плана), **Программа** (редактор плана, пресеты), **История** (разворачиваемые записи), **Профиль**.

Тарифы: AI Free — 10 сообщений коуча в день и одна программа; AI Pro — безлимит, генератор программ, разбор техники, экспорт. Счётчик обновляется в 00:00 UTC.

**С версии 0.35 профиль, тариф, счётчик коча и история диалога хранятся на сервере.** Раньше они лежали в `localStorage` и терялись при очистке хранилища или смене устройства. Теперь источник правды — БД; локально остаётся только кэш для первой отрисовки.

PWA: `manifest.webmanifest` + `sw.js`. Кэш service worker — `gymai-v3`; **при изменении статики версию поднимать**, иначе пользователи получат старую версию из кэша.

## Что стоит знать при доработке

**`index.html` на 243 КБ — один файл.** Первое, что стоит сделать при развитии проекта: разнести на модули. Редактировать в таком виде больно.

**База упражнений захардкожена в `index.html`.** В редакторе программы есть поиск по каталогу, но сам каталог — массив в коде. Для мультипользовательской версии нужна таблица.

**Полный каталог упражнений лежит в `prototypes/`, а не в основной версии.** В `index.html` только 11 записей в `exerciseGuides` без полей `zone` / `muscle` / `tech`. Полные 53 упражнения с описанием техники и привязкой к 9 мышечным зонам — в `prototypes/exflow/`, оттуда же вынесен `exercise_library.json`. Форматы основной версии и прототипа несовместимы, при внедрении нужно свести к одному. Подробности в `prototypes/README.md`.

**Админка теперь серверная.** Секрет админа в коде страницы больше не лежит: клиент обменивает его на короткоживущий токен (`adm_...`, 12 ч) через `POST /api/admin/login`, дальше ходит с `Authorization: Bearer`. Экран открывается только по хешу `#admin`, в навигации ссылки нет.

**Сессии не имеют срока жизни.** Токен в БД живёт бессрочно. Если понадобится — добавить `expires_at` в таблицу `sessions`.

**`reserveCoach` возвращает `used` на единицу устаревшим** — считает значение до `UPDATE`. На лимит не влияет (проверка идёт по `rowsAffected`), но в ответе `402` число неверное.

**Лимит coach обновляется в 00:00 UTC.** Серверное время, не локальное.

**Публикация мини-апа** идёт через платформу mira.tg, не через GitHub Pages. `index.html` в репозитории — источник, публикация — отдельный шаг.

## Что уже сделано и проверено

- HMAC-проверка initData с `timingSafeEqual`, отсечкой по возрасту и защитой от битого ввода
- Вебхук требует `TG_WEBHOOK_SECRET`, сравнение константное
- Квота AI-коуча резервируется атомарно до вызова и возвращается при ошибке
- `upsertUser` пишет только переданные поля — без гонки чтения-записи
- Пустой ответ модели не показывается пользователю: перебор фолбэков, `reasoning` не используется
- Таймаут запросов к AI, битый JSON отдаёт 400, внутренние ошибки наружу не утекают

## Грабли, на которые уже наступали (v0.36)

1. **`SRV.push` ронял строковые значения.** Ключи `gymai_name`, `gymai_experience`,
   `gymai_reminders`, `gymai_theme` пишутся в `localStorage` обычной строкой, а
   `push()` делал `JSON.parse(raw)` — парсинг бросал исключение, ключ молча
   терялся, и данные не доходили до сервера. Теперь строка упаковывается в
   `{__raw}` и разворачивается обратно через `srvDecode()`.

2. **Объектная форма `client.execute({sql, args})` на Turso возвращает пустой
   результат.** `getStateByOwner()` использовала именно её — состояние читалось
   пустым. Рабочая форма — позиционные аргументы: `client.execute(sql, args)`.
   Проверять на живой базе, а не в песочнице: из песочницы доступа к БД нет,
   все запросы молча возвращают 0 строк.

3. **Дубликат маршрута перехватывал запрос.** Два `app.put('/api/admin/plan')`
   подряд: работал только первый, а правка попадала в мёртвый код. Дубликаты
   маршрутов в `server.js` надо искать до деплоя.

4. **Список синхронизируемых ключей нельзя держать константой.** Состав
   тренировки лежит в динамических ключах `gymai_setup_<номер дня>` — они
   выпадали из синка. Правило вынесено в `srvIsDataKey()` / `srvDataKeys()`.

5. **Деплой клиента на Pages.** Архив репозитория целиком не подходит: в нём
   лежит `HANDOFF.md`, а Pages принимает только статику. Собирать zip только
   из файлов корня (`index.html`, `install.html`, `manifest.webmanifest`,
   `sw.js`, иконки) — прототипы из `prototypes/` перезаписывают `index.html`,
   если их не отфильтровать по пути.

6. **После каждого изменения клиента поднимать `CACHE` в `sw.js`** — иначе
   старый service worker продолжит отдавать прежний файл.

## Тесты без браузера (v0.36)

Клиент — один `index.html`, поэтому для проверки логики есть офлайн-стенд:
`tests/run.js`. Он сам достаёт разметку `<body>` и главный inline-скрипт из
`index.html`, поднимает минимальный DOM-шим и гоняет настоящий код клиента.

```
node tests/run.js            # все наборы
node tests/run.js feature    # светлая тема + удаление упражнения
node tests/run.js regression # регрессия v0.36
node tests/run.js sync       # синхронизация с сервером
```

Зависимостей нет — только Node (проверено на Node 24). `npm install` в
песочнице недоступен, поэтому `jsdom` использовать нельзя: свой шим.

Всего 61 тест в трёх наборах:

* **feature (22)** — переключение темы (сохранение, класс `light-theme`,
  `data-theme`, кнопка, переживание перезапуска), удаление упражнения из
  тренировки (переиндексация подходов, сохранение в `localStorage`, удаление
  последнего).
* **regression (21)** — правила синхронизации
  (`srvIsDataKey`/`srvDataKeys`/`srvDecode`), `clearDeviceData`, смена аккаунта
  без протечек, `startFromPlan` и round-trip черновика.
* **sync (17)** — `syncAll()` на поддельном сетевом слое: серверное значение
  применяется, строка-маркер `{__raw}` разворачивается, ключ, которого нет на
  сервере, удаляется, а токены не трогаются и не отправляются; отдельно
  проверяется двойная защита списков `SRV_KEYS` / `SRV_LOCAL_ONLY`.

Шим намеренно простой: `El`, `ClassList`, `Storage` и мини-парсер HTML.
У него есть особенность — `.click()` зовёт и `onclick`, и зарегистрированные
через `addEventListener` обработчики, а `innerHTML` пересобирает дерево
элементов. Это нужно учитывать, расширяя стенд.

### Стенд надо проверять мутациями

Зелёный прогон ничего не значит, пока тесты не проверены на «сломанном» коде.
Проверка делается так: копия `index.html` правится в одном месте, стенд
запускается на ней, ожидается падение, оригинал возвращается на место.

Так были пойманы три поломки, которые тесты поначалу пропускали: отказ от
переиндексации подходов, отказ сохранять тему и отказ применять класс
`light-theme`. И — важнее всего — **набор `sync` не попал в закоммиченный
раннер**, из-за чего утечка токенов на сервер, «любой ключ считается
данным» и «серверное значение не применяется» проходили незамеченными.
Мутационный прогон обязателен после каждого расширения наборов.

Полезные мутации для проверки стенда:

| Что ломаем | Что должно упасть |
|---|---|
| `else if(n>i)ns[n-1]=draft.sets[k]` → `ns[n]` | «подходы переиндексированы» |
| `localStorage.setItem(THEME_KEY,mode)` убрать | «тема сохранена в localStorage» |
| `classList.toggle('light-theme',...)` убрать | «класс light-theme на documentElement» |
| `if(SRV_KEYS.indexOf(k)>=0)return true;` → `if(true)return true;` | «случайный чужой ключ не считается данными» |
| `if(v===null||v===undefined)continue;` убрать в `syncAll` | «удалённое значение применяется» |
| `gymai_acct_token` добавить в `SRV_KEYS` **и** снять `SRV_LOCAL_ONLY` | «токены не считаются данными», «токен аккаунта остался на месте» |

### Двойная защита на токенах — важная деталь

`SRV_LOCAL_ONLY` проверяется **раньше** `SRV_KEYS`, и токенов нет ни в одном
из списков. Поэтому снятие **одной** половины не меняет ничего: если
`gymai_acct_token` добавить в `SRV_KEYS`, он всё равно отсечётся вторым
списком, и наоборот. Это не дыра, а эшелонированная защита.

Настоящая утечка требует сломать **оба** списка сразу — именно такая
комбинированная мутация и ловится набором `sync`. Проверять стенд нужно
комбинациями, а не по одному: одиночная мутация «не поймана» здесь означает
не слабость теста, а наличие второй линии защиты.

Ещё одна ловушка при проверке мутациями: паттерн надо искать в коде
заранее. Первая попытка снять «серверное значение не применяется» попала в
совершенно другое место (`if(!v)return` в обработчике имени упражнения) и
ничего не сломала — выглядело как дыра в тестах, но это была ошибка самой
мутации.
